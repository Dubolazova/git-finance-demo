# Инструкция для ИИ: учебная работа с репозиторием

Используйте в Codex, Claude Code или другом агенте, у которого есть инструменты работы с файлами и Git. Обычный чат с GitHub-контекстом может только прочитать проект или подготовить текст для ручного сохранения. Сначала проверьте реальные возможности текущего инструмента.

## Что заполняет пользователь

- Репозиторий: вставьте ссылку на свой `git-finance-demo`.
- Исходная ветка: `main`.
- Задача: добавить в README правило проверки результата.
- Данные: только учебные, без сведений о клиентах.

Логин и подтверждение разрешений выполняйте на страницах GitHub и сервиса ИИ. Не передавайте в чат пароль, коды входа или токены. Для приватного проекта у агента должно быть отдельно разрешение на этот репозиторий.

## Запрос 1. Проверить доступ и подготовить правку

Скопируйте текст и замените ссылку:

```text
Работаем с учебным репозиторием: [вставьте ссылку].
Исходная ветка main. Я не разработчик, объясняй действия простыми словами.

Сначала проверь:
1. Видишь ли ты README этого репозитория? Приведи его заголовок.
2. Есть ли у твоего текущего инструмента права менять файлы и выполнять Git-операции?
3. Есть ли права отправлять ветки в этот репозиторий на GitHub?

Если у тебя только чтение или нет доступа, сообщи об этом. Не утверждай,
что что-то сохранил или отправил. Подготовь текст для ручного применения.

Если доступ к изменению есть, обнови сведения об основной ветке и создай
от неё отдельную ветку для учебной правки. Имя может назначить сервис.
Не перезаписывай чужие или несохранённые изменения.

Меняй только README.md. Добавь строку:
«Перед использованием результат проверяет ответственный специалист».
Если строка уже есть, не дублируй её и сообщи, что изменение не требуется.

Покажи точную разницу до и после. Проверь, что изменён только README,
строка встречается один раз и прежний текст сохранён.
Код приложения и настройки проекта менять не нужно.

Пока не объединяй изменения в main и не запускай публикацию приложения.
Если твоя облачная среда автоматически сохраняет и отправляет изменения
в свою ветку, сообщи об этом и укажи ветку. Сам PR тоже не объединяй.
```

## Запрос 2. Сохранить и отправить проверенную правку

После просмотра результата отправьте:

```text
Правку README проверил(а). Сохрани её в текущую отдельную ветку.
Сообщение коммита: «Добавлено правило проверки результата».
Отправь ветку в исходный репозиторий на GitHub обычным push.
Если эти действия уже выполнила среда, повторно ничего не создавай.

Создай pull request в main, если у инструмента есть такое право.
Заголовок: «Правило проверки калькулятора».
Описание: «В README добавлено правило проверки результата.
Код приложения и расчёты не менялись. Проверено отсутствие дубликата строки».
Не выполняй merge, force push, удаление истории или публикацию приложения.

В ответе укажи:
- имя ветки;
- идентификатор коммита и статус отправки на GitHub;
- ссылку на pull request, если он создан;
- что нужно проверить человеку следующим шагом.

Если действие недоступно, сообщи точную причину и дай короткий путь
через GitHub Desktop или GitHub в браузере. Не заменяй выполненное действие
инструкцией без явного пояснения.
```

## Как пользователь проверяет результат

Откройте репозиторий на GitHub. Выберите указанную агентом ветку. Убедитесь, что README содержит новую строку и в истории виден коммит. Откройте PR и Files changed: измениться должен только README. Для переноса правки в main нужен отдельный шаг merge после проверки ответственным участником.

Если вы выполняете commit и push сами, откройте ту же локальную папку в GitHub Desktop. Проверьте Current Branch и Changes, напишите Summary, нажмите Commit to нужная-ветка, затем Publish branch или Push origin. Для облачной ветки сначала получите её локально либо проверьте её прямо на GitHub.
